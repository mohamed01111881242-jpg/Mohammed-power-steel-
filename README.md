# النظام الخارق للمعارف

منصة عربية متعددة الأطراف تربط الشركات والمقاولين والورش والمصانع والمهنيين والموردين والعملاء.

## الموجود حاليًا
- واجهة عربية RTL متجاوبة داخل `index.html`.
- تسجيل الدخول برقم الهاتف ورمز OTP عبر Supabase Auth (يتطلب إعداد مزود الرسائل).
- تسجيل النشاط التجاري وربط مالكه بعضوية `owner` في معاملة قاعدة بيانات واحدة.
- دليل عام للأنشطة التي تسمح بالظهور، مع نوع النشاط والتخصص والمنطقة وبيانات التواصل.
- مطابقة أولية للطلبات حسب المنطقة والتخصص، مع إمكانية الانتقال مباشرة لتقديم عرض.
- نشر طلبات التنفيذ والتصنيع والتوريد والعمالة والمنتجات في قاعدة البيانات المشتركة.
- إرسال عروض أسعار مرتبطة بطلب وبنشاط مقدم العرض.
- قبول أو رفض العروض من صاحب الطلب؛ وعند القبول يُغلق استقبال العروض الأخرى تلقائيًا.
- استقبال رسائل WhatsApp عبر Webhook آمن وتخزين المحادثات، مع ردود ذكاء اصطناعي عند إعداد أسرار Meta وOpenAI.
- صلاحيات صفوف RLS لعزل بيانات العضويات والطلبات والعروض.
- اشتراكات مجانية ومدفوعة وفق السياسة المعتمدة: 30 يومًا، سماح 7 أيام، وتجديد يدوي افتراضيًا.

## تشغيل الواجهة
يمكن فتح `index.html` أو نشره عبر GitHub Pages من Settings → Pages → Deploy from a branch → main → /(root)، إذا كانت الخاصية متاحة.

## إعداد قاعدة البيانات
المشروع الحالي موجود في Supabase باسم `al-maaref-platform`. لا تُعد تشغيل `schema.sql` على قاعدة البيانات الحالية؛ الجداول موجودة بالفعل. راجع ملفات الترحيل في `supabase/migrations/` وسجل الترحيلات في Supabase.

## حماية المفاتيح
مفتاح Supabase publishable الموجود في الواجهة مخصص للمتصفح. لا تضع أبدًا `service_role` أو مفاتيح سرية أو WhatsApp access token أو مفاتيح الذكاء الاصطناعي داخل `index.html` أو GitHub.

## WhatsApp Webhook
تم نشر الوظيفة `whatsapp-webhook` على Supabase. عنوان الاستقبال:
`https://llkxjglbxxsrhagjfhqx.supabase.co/functions/v1/whatsapp-webhook`

تحتاج إلى أسرار الخادم الموضحة في `supabase/SETUP.md` قبل أن يبدأ التحقق من Meta والردود التلقائية.

## ما زال مطلوبًا قبل التشغيل التجاري الكامل
- إعداد مزود SMS في Supabase واختبار تسجيل OTP على رقم حقيقي.
- إضافة حساب المؤسس إلى `platform_admins` بعد تحديد حسابه الموثق.
- ربط WhatsApp Business Cloud API بعد تجهيز Meta Business ورقم مؤهل وبيانات Webhook.
- اختيار بوابة دفع مصرية وربط تأكيد المدفوعات من الخادم فقط.
- إضافة مزود نموذج ذكاء اصطناعي ومفتاحه في أسرار الخادم لتفعيل المساعد الذكي.
- استكمال اختبارات RLS بحسابين أو أكثر، واختبار الهاتف والأجهزة المختلفة.
- تطبيق حدود الخطط المدفوعة داخل عمليات قاعدة البيانات قبل تحصيل الاشتراكات.

**قاعدة تشغيل:** لا يعتمد النظام عرض سعر نهائيًا أو اتفاقًا ماليًا تلقائيًا؛ يظل القرار لصاحب الصلاحية.
